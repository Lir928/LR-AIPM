# 老项目页面还原流水线

## 触发词

`执行页面还原`、`还原老页面`、`还原旧页面`

## 流水线概述

本流水线用于将 Chrome 扩展导出的老系统页面数据包，**忠实还原**为 Axhub Make 原型页面。

核心原则：**还原不是重做**。目标是尽量 1:1 像素级还原原页面的视觉与布局，不主动改版、不擅自简化。

与 `04-原型生成流水线` 的根本区别：
- `04` 从 PRD + Prompt 创造新页面（可以发挥设计创意）
- `10` 从导出数据包还原旧页面（必须忠实原貌）

## 什么时候使用本流水线

- **适用**：你手里有一个完整的 Chrome 扩展导出包（含 manifest.json、screenshot.png、theme.json、flat/ 等），目标是让原型**看起来跟老系统一样**
- **不适用**：你是从零开始设计新页面（应走 `02 -> 07 -> 04`）；或者你只是想参考老页面的部分元素做新设计（应走 `00 -> 02 -> 04`）

## 输入材料位置

导出包应放在以下位置之一：

- `workbench/_incoming/YYYY-MM-DD/<页面名>/` — 临时暂存
- `projects/[项目名称]/legacy-assets/<页面名>/` — 长期归档

## AI 协同顺序与执行逻辑

### 步骤 1：数据注入（强制执行）

**目的**：让 AI 精确掌握原页面的完整信息，而不是靠印象猜测。

**必须执行以下操作**：

1. 读取 `manifest.json`，确认导出包的能力和文件清单
2. 读取 `screenshot.png`，将截图作为视觉真相的**最高优先级参考**
3. 读取 `theme.json`，提取精确的设计令牌（颜色、字体、间距、阴影、圆角、动画）
4. 使用 `query.mjs` 渐进式读取骨架结构：

```bash
# 先看摘要
node axhub-make/skills/clone-page/scripts/query.mjs <导出包目录> summary

# 再看骨架（控制深度，避免上下文溢出）
node axhub-make/skills/clone-page/scripts/query.mjs <导出包目录> skeleton --depth=2

# 查看各 section
node axhub-make/skills/clone-page/scripts/query.mjs <导出包目录> sections

# 逐段查看关键 section 的 DOM + 样式
node axhub-make/skills/clone-page/scripts/query.mjs <导出包目录> section <section-name>
```

5. 读取 `content.md`，校准文本内容和字段名称
6. 读取 `flat/index.json`，了解节点分类（interactive 节点、角色标注等）

**数据优先级**（当数据冲突时，以高优先级为准）：

| 优先级 | 数据源 | 说明 |
|--------|--------|------|
| ⭐⭐⭐⭐⭐ | screenshot.png | 截图是最终真相，所有冲突以截图为准 |
| ⭐⭐⭐⭐ | theme.json | 精确的颜色/字体/间距值 |
| ⭐⭐⭐ | flat/skeleton.json + flat/index.json | DOM 层级与语义标签 |
| ⭐⭐ | content.md | 文本内容校准 |
| ⭐ | flat/nodes/*.json + flat/styles/*.json | 逐节点精确样式（按需查取） |

**关键约束**：禁止跳过本步骤直接进入步骤 2。如果 AI 上下文不足以容纳全部数据，必须使用 `query.mjs` 渐进查询，分批注入。

### 步骤 2：主题提取

**目的**：把导出包里的 `theme.json` 转为 Axhub Make 可用的主题目录，让还原原型直接引用精确的设计令牌。

**操作**：

1. 在 `axhub-make/src/themes/` 下创建 `<原系统名>-restored/` 目录
2. 从 `theme.json` 中提取以下字段，生成 `globals.css`：

```
colors → CSS 变量（--color-primary, --color-text 等）
typography → 字体族、字号、行高、字重
spacing → 间距令牌
shadows → 阴影令牌
radius → 圆角令牌
```

3. 生成 `designToken.json`，保持原值不做近似替换
4. 生成 `DESIGN.md`，注明"本主题来自老系统导出数据还原，非新建设计"
5. 在 `spec.md` 中声明使用该还原主题

**关键约束**：颜色值必须使用 `theme.json` 中的原始值（如 `rgb(24,144,255)`），不得用 Element UI 或 Ant Design 的默认值猜测替换。

### 步骤 3：逐段还原原型代码

**目的**：按 section 分段还原，而不是整页一次性生成，降低 AI 单次处理复杂度。

**操作**：

1. 从 `sections/` 目录和 `flat/index.json` 中确认页面分段
2. 按 header → sidebar → main-content → footer 的顺序，逐段生成代码
3. 每段还原时，必须：
   - 对照 `screenshot.png` 中的对应区域
   - 使用 `theme.json` 中提取的精确样式值
   - 使用 `query.mjs section <name>` 查取该段的 DOM + computedStyle
4. 将所有代码直接写入 `axhub-make/src/prototypes/<pageId>/` 下的文件

**关键约束**：
- 所有样式值（颜色、字号、间距、圆角、阴影）必须来自 theme.json 或 screenshot，不得凭猜测使用默认值
- 原页面的交互元素（下拉菜单、弹窗、Tab 切换、表单控件）必须逐一还原，不得省略
- 原页面使用 Element UI / VXE Table 等组件库的样式特征必须保留（用 antd 或自定义 CSS 模拟）
- 原页面的数据表格必须还原完整列结构，mock 数据应多样化而非全部相同

### 步骤 4：CSS 属性校验

**目的**：逐项对照原页面的核心视觉属性，确保还原精度。

**校验清单**（在 `spec.md` 中记录每一项的还原状态）：

| 属性类别 | 校验内容 | 来源 |
|----------|----------|------|
| 主色 | primary color 精确值 | theme.json colors |
| 文本色 | text color 层级（primary/secondary/tertiary） | theme.json typography |
| 字体族 | font-family 精确字符串 | theme.json fonts |
| 字号体系 | 各层级 fontSize + lineHeight | theme.json typography |
| 间距体系 | padding/margin 核心值 | theme.json spacing |
| 圆角 | borderRadius 值及使用场景 | theme.json radius |
| 阴影 | boxShadow 值及使用场景 | theme.json shadows |
| 边框色 | borderColor 层级 | theme.json borders |
| 动画 | transition/animation 名称与时长 | theme.json animations |
| 交互态 | hover/focus/active/disabled 样式差异 | screenshot + nodes.json |

### 步骤 5：视觉校验

**目的**：对比还原原型与原截图，量化还原精度。

**操作**：

1. 启动 Axhub Make 预览：`npm run dev:axhub-make`
2. 访问 `/prototypes/<pageId>`，确认页面无构建/运行时错误
3. 运行验收脚本：`node axhub-make/scripts/check-app-ready.mjs /prototypes/<pageId>`
4. 人工（或让 AI）逐项对照 `screenshot.png` 与原型渲染结果，列出以下差异：
   - 布局偏差（区域位置、宽度比例）
   - 颜色偏差（色值差异）
   - 字体偏差（字族、字号、字重差异）
   - 缺失交互（原页面有但原型未实现的交互行为）
   - 缺失组件（原页面有但原型未实现的 UI 元素）
5. 将差异清单写入 `spec.md` 的"还原偏差记录"章节

### 步骤 6：偏差修复（可选）

如果步骤 5 发现还原偏差较大（视觉精度低于 80%），执行修复循环：

1. 对照差异清单，逐项修复原型代码
2. 重新运行验收脚本
3. 重新对照截图校验
4. 重复直到视觉精度达到可接受水平或用户确认满意

## 执行前提

- Chrome 扩展导出包已存在（含 manifest.json、screenshot.png、theme.json 等）
- Axhub Make 本地引擎已安装并可运行
- Node.js >= 18（query.mjs 需要）

## 预期成果

- 在 `axhub-make/src/prototypes/<pageId>/` 下生成还原原型
- 在 `axhub-make/src/themes/<原系统名>-restored/` 下生成还原主题
- `spec.md` 包含逐项 CSS 属性校验记录和还原偏差记录
- 原型视觉精度目标：≥ 85% 与原截图一致
- 原型功能精度目标：原页面所有可见交互行为均已实现

## 与其他流水线的关系

- 本流水线**替代**场景 B 中 `02 -> 04` 的组合（还原场景不需要走 PRD -> Prompt 路径）
- 盘点阶段 `01` 仍可作为可选前置（如果需要理解老系统全局架构）
- 完成后正常走 `09` 归档
- 如果还原后需要改版升级，再走 `02 -> 03 -> 04`

## 注意事项

- **不主动改版**：还原目标就是"跟原来一样"，不是"做得更好"。如果用户想改版，请先完成还原，再在还原基础上迭代
- **不省略交互**：原页面的每个下拉菜单、弹窗、Tab、筛选器都必须还原，即使交互逻辑简化，UI 样式也必须保留
- **不猜测样式**：所有视觉属性必须从导出数据中取值，不得用 Ant Design / Element UI 默认值替代
- **不合并段落**：整页还原时必须分段处理，避免单次上下文溢出导致精度下降
- **截图是最终真相**：当 theme.json 的数值与截图视觉冲突时，以截图为准
