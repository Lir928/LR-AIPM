# 原型深度补强流水线（可选）

## 触发词

`执行原型增强`

## 流水线概述

在已有基础原型后，本流水线用于对 Axhub 原型代码做**深度补强**，注入更复杂的交互、状态管理和业务逻辑。

它不是默认下一步，因为 `04` 已经应当完成基础交互与演示逻辑。

只有在以下情况才进入本流程：

- `04` 后仍缺少复杂状态机
- 需要更真实的接口联动
- 需要重型 CRUD 或多模块联动演示
- 需要对既有原型做较大幅度返修

## AI 协同顺序与执行逻辑

- 【步骤 1：读取基础原型与 PRD】：主动定位并读取 `axhub-make/src/prototypes/[页面英文ID]/` 目录下的基础原型代码（`index.tsx` 等），同时读取对应的 PRD 文档获取真实的业务规则。
- 【步骤 2：专家技能介入】：强制调用 `.skills/` 里的高级研发专家（如 `@crud-implementation`、`@ui-ux-pro-max` 等），根据 PRD 的状态机和数据字典，设计真实的前端交互逻辑。
- 【步骤 3：直接重写 Axhub 代码 (Hard Rule)】：将所有复杂的业务逻辑、状态管理（Hooks）、网络请求等，【直接写入并覆盖】 `axhub-make/src/prototypes/[页面英文ID]/` 下的代码文件！绝对禁止在其他任何地方创建独立的 src 目录！
- 【步骤 4：交付预览】：在聊天框向用户反馈：
  - "✅ 研发技能已成功注入！您的 Axhub 原型现已具备真实业务逻辑。"
  - "🔗 请在当前 Axhub Make 启动时终端输出的 Local URL 下，刷新 /prototypes/[页面英文ID] 体验完全体（端口可能自动变化）。"

## 执行前提

- `axhub-make/src/prototypes/<pageId>/` 中已存在可运行原型
- 对应工作台 PRD 已基本稳定
- 当前目标是提升交互真实度，而不是重新生成基础结构
- 如果只是补一个普通弹窗、筛选或状态切换，优先直接在 `04` 或手工迭代阶段解决，不必进入本流程
