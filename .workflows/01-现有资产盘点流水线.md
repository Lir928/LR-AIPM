# 现有资产逆向学习流水线

## 触发词

`执行老项目盘点`

## 流水线概述

本流水线用于在“升级现有页面”之前，读取旧系统已有资产（代码、数据库 Schema、接口文档、历史 PRD、旧页面 HTML 等），建立全局上下文并生成逆向报告，确保后续 PRD 和原型不会偏离既有约束。

本流水线是**可选前置**，不是默认必跑步骤。

## 什么时候执行

- **适用**：
  - 你正在升级旧系统页面
  - 手头材料很多，且不只是一张截图
  - 你需要先理解旧系统规则、数据结构、接口契约
- **不适用**：
  - 新增需求/新页面
  - 只是页面小改版
  - 只有少量材料，人工已能快速判断结构

如果不适用，直接跳过，进入 `02 -> 07 -> 04/直接改原型 -> 03 -> 09`；只有复杂返修时再补 `08`。

## 输入材料建议位置

- 页面级输入材料建议先放：
  - `workbench/_incoming/YYYY-MM-DD/<页面名或pageId>/`
- 项目级、长期需要保留的旧系统资产建议放：
  - `projects/[项目名称]/legacy-assets/`

如果只是本次升级临时参考，不必强行放进 `legacy-assets/`。

## AI 协同顺序与执行逻辑

### 步骤 1：汇总盘点范围

- **任务**：判断要盘点的是“单页面输入材料”还是“整套遗留系统资产”。
- **输出**：明确材料来源与分析边界。

### 步骤 2：历史文档知识提取

- **技能**：@legacy-doc-analyzer
- **任务**：读取 `projects/[项目名称]/legacy-assets/` 目录下的各种非结构化文档（Word、Markdown、txt 等），提炼业务规则、专有名词（Glossary）和隐藏逻辑。
- **输出**：在 `projects/[项目名称]/legacy-assets/reports/` 生成 `00-历史文档分析报告.md`。

### 步骤 3：存量接口解析

- **技能**：@api-doc-parser
- **任务**：解析 `projects/[项目名称]/legacy-assets/` 目录下的 API 接口文档，提取接口定义、参数说明和返回值结构。
- **输出**：在 `projects/[项目名称]/legacy-assets/reports/` 生成 `00-接口分析报告.md`。

### 步骤 4：拓扑与架构扫描

- **技能**：@codebase-mapper
- **任务**：全局扫描 `projects/[项目名称]/legacy-assets/` 目录下的老代码和旧文档，梳理模块依赖关系。
- **输出**：在 `projects/[项目名称]/legacy-assets/reports/` 生成 `01-系统现存架构图.md`。

### 步骤 5：数据资产逆向解析

- **技能**：@schema-reverse-engineer
- **任务**：提取 `projects/[项目名称]/legacy-assets/` 中的代码类型定义、建表 SQL 或老 API 文档，逆向出实体关系图。
- **输出**：在 `projects/[项目名称]/legacy-assets/reports/` 生成 `02-现存数据字典.md`。

### 步骤 6：业务规则还原与基线确认

- **技能**：@reverse-prd-generator
- **任务**：结合上述步骤，总结出系统目前已经实现了哪些功能，梳理出存量 PRD，并圈出高风险代码区域。
- **输出**：在 `projects/[项目名称]/legacy-assets/reports/` 生成 `03-存量业务逻辑基线.md`。

## 后续动作

若执行过本流水线，则输出报告作为后续 [02-需求转PRD流水线](./02-需求转PRD流水线.md) 与 [04-原型生成与基础增强流水线](./04-原型生成与基础增强流水线.md) 的前置上下文；复杂场景下也可继续作为 `08` 的补强依据。

若未执行本流水线，则直接以工作台 PRD 与 Prompt 作为当前阶段的唯一事实来源推进。
