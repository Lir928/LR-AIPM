# 页面还原常见问题排查

## 🚨 还原质量不佳的排查清单

### 1. 颜色不准确
**现象**：还原页面颜色与原图有色差
**原因**：
- AI未读取`theme.json`中的精确颜色值
- 使用了Ant Design默认配色代替原始颜色

**解决方案**：
1. 验证`theme.json`是否存在并包含足够的颜色数据
2. 检查生成的主题文件中是否有精确的RGB值
3. 重启还原流程，确保AI优先使用`theme.json`数据

### 2. 字体不匹配  
**现象**：文字字体、字号与原图不符
**原因**：
- AI未使用`theme.json`中的字体族
- 默认使用了系统字体

**解决方案**：
1. 检查`theme.json`中的`typography.families`是否包含字体信息
2. 确认生成的设计令牌包含了正确的字体设置
3. 在样式中显式指定字体族

### 3. 间距不对称
**现象**：元素之间的间距不均匀
**原因**：
- AI没读取`theme.json`中的间距数据
- 使用了默认的Tailwind间距

**解决方案**：
1. 验证`theme.json`中的`spacing`数组是否包含间距信息
2. 确认主题生成时提取了正确的间距值
3. 在CSS中使用精确的间距值

### 4. 布局结构错误
**现象**：页面布局与原图不一致
**原因**：
- 没充分利用`skeleton.json`的DOM结构
- AI凭印象重构而未忠实还原

**解决方案**：
1. 检查`skeleton.json`是否提供了足够的结构信息
2. 使用`query.mjs`工具渐进式读取DOM结构
3. 分段还原，每段对照截图验证

### 5. 交互元素缺失
**现象**：原页面的按钮、表单等交互元素丢失
**原因**：
- AI忽略了`flat/nodes/`中的交互信息
- 只关注视觉还原，忽略功能还原

**解决方案**：
1. 检查`flat/nodes/`目录中的交互元素信息
2. 还原时确保所有可点击元素都被还原
3. 验证表单、弹窗、Tab等交互功能

## 📋 数据完整性检查

### 检查导出包是否完整
运行集成测试脚本：
```bash
node axhub-make/scripts/integration-test-restoration.mjs <导出包路径>
```

### 关键文件检查清单
- [ ] `screenshot.png` - 页面截图（最重要）
- [ ] `theme.json` - 设计令牌（颜色、字体、间距）
- [ ] `content.md` - 文本内容
- [ ] `manifest.json` - 页面元数据
- [ ] `sections/` - 页面分段（关键）
- [ ] `structure/doms.json` - DOM结构
- [ ] `flat/skeleton.json` - DOM骨架
- [ ] `flat/index.json` - 节点索引

## ⚠️ 常见陷阱

### 1. 上下文溢出
**问题**：AI一次读取过多数据导致细节丢失
**解决**：使用`query.mjs`分批次读取数据，避免一次性传输大文件

### 2. 数据优先级错误
**问题**：AI优先使用PRD而非导出包数据
**解决**：确保在还原流程中强制优先读取导出包数据

### 3. 颜色值近似化
**问题**：AI将RGB值转换为接近的Ant Design色系
**解决**：强制使用原始RGB值，不进行颜色近似

### 4. 整页一次性生成
**问题**：试图一次性生成整个页面导致精度下降
**解决**：按`sections/`分段逐步生成

## 🔧 精度优化技巧

### 提升还原质量的方法
1. **数据渐进注入**：先读摘要，再读结构，最后读细节
2. **分段验证**：每生成一段就对照截图验证
3. **主题先行**：先生成精确主题，再应用到页面
4. **视觉验证**：每步完成后进行视觉对比

### 验证还原质量的标准
- [ ] 颜色值完全一致（检查DevTools中的RGB值）
- [ ] 字体族、大小、粗细一致
- [ ] 间距、圆角、阴影一致
- [ ] 布局结构保持一致
- [ ] 交互元素完整保留
- [ ] 视觉相似度≥85%

## 🎯 快速修复指南

### 小幅修正
1. 直接编辑生成的原型文件
2. 使用DevTools对比样式差异
3. 参考`theme.json`中的精确值调整

### 大幅重做
1. 清理已生成的文件
2. 重新执行还原流程
3. 确保AI严格按照导出包数据执行

---

**提醒**：还原的目标是**精确复刻**，不是**重新设计**。遇到问题时，始终以`screenshot.png`为最终参考标准。
