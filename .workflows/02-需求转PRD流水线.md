# 需求转PRD与原型提示词流水线

## 触发词

`执行需求梳理`

## 流水线概述

本流水线用于将原始业务需求、会议纪要、零散想法，或旧页面升级目标，结构化为标准 PRD，并生成用于 Axhub Make 的 Prompt。

这是主线中的**第一个核心步骤**。通常在你确认入口类型后，就应该进入本流程。

前置建议：

- 新增页面：可直接进入本流程
- 升级外部页面：先确认输入材料已放入 `workbench/_incoming/...`
- 升级已归档页面：建议先恢复工作台再进入本流程

## AI 协同顺序与执行逻辑

### 步骤 1：明确项目与页面标识

- **任务**：先明确项目名称、页面中文名、页面英文 ID（kebab-case）。
- **输出**：确认后的 `projectName`、中文名、`pageId`。

### 步骤 2：整理输入上下文

- **任务**：读取用户输入、会议纪要、旧页面材料或盘点报告，确定本次改什么、不改什么。
- **输出**：最小可执行需求边界。

### 步骤 3：需求提炼与结构化

- **技能**：@prd
- **任务**：输出包含业务背景、范围、角色、关键流程、字段与验收标准的结构化 PRD。
- **输出**：结构化需求文档（草稿）。

### 步骤 4：逻辑闭环设计

- **技能**：@requirements-to-detailed-design + @enterprise-product-designer
- **任务**：针对步骤 3 的文档，强制使用 Mermaid 语法绘制状态机和业务流转图，确保异常分支和边界条件无遗漏。同时应用企业级 B 端产品设计规范，为每个核心页面绘制 ASCII 布局图，并输出包含字段名、数据类型、校验规则的严谨表格。
- **输出**：带有时序图、流程图、ASCII 布局图和字段级描述表格的完整 PRD。

### 步骤 5：生成 Axhub 原型 Prompt

- **技能**：@requirements-closure-designer (或自定义 @axhub-prompt-generator)
- **任务**：基于定稿的 PRD，提炼出专供 Axhub Make 读取的页面布局与 UI 组件描述 Prompt。
- **输出**：Axhub 专属 Prompt 文本。

### 步骤 6：文件命名与存储

- **任务**：根据当前日期和确认的需求/功能名称，生成标准化的文件名，并存储在固定的业务目录中：
  - 工作台 PRD（正本）：`axhub-make/src/docs/[页面英文ID]-PRD.md`
  - 迭代需求材料：`projects/[项目名称]/features/[页面英文ID]/iterations/YYYYMMDD-[功能名称].md`
  - Prompt（正本）：`projects/[项目名称]/features/[页面英文ID]/prompts/YYYYMMDD-[功能名称]-Prompt.md`
  - （可选）索引引用：`projects/[项目名称]/docs/YYYYMMDD-[功能名称].md`、`projects/[项目名称]/prompts/YYYYMMDD-[功能名称]-Prompt.md`（仅做引用/索引）
- **输出**：生成的文件路径。

### 步骤 7：IDE 焦点控制

- **任务**：文件生成完毕后，调用编辑器的能力，自动在主视窗打开刚刚生成的工作台 PRD（`axhub-make/src/docs/[页面英文ID]-PRD.md`），以便用户进行确认和手动编辑。
- **输出**：编辑器打开的文件。

### 步骤 8：标准接力提示语与下一步建议

- **任务**：在完成上述动作后，明确告诉用户下一步应该是“启动预览”“执行原型生成”还是“先直接修改原型”。
- **输出**：标准接力提示语。

## 预期成果

- 工作台阶段可直接在文档 Tab 看到的 PRD（正本）：`axhub-make/src/docs/[页面英文ID]-PRD.md`
- 可视化的 Mermaid 业务流程图。
- 可直接复制到 Axhub Make 生成原型的精确提示词（正本），存储在 `projects/[项目名称]/features/[页面英文ID]/prompts/YYYYMMDD-[功能名称]-Prompt.md`。
- 自动打开的 PRD 文件，方便用户编辑确认。
- 标准的接力提示语，引导用户进入 `07`、`04`、或直接修改原型。

## 标准接力提示语

```
✅ PRD 与 Prompt 已生成。已为您打开工作台 PRD（`axhub-make/src/docs/[页面英文ID]-PRD.md`），并生成了 Prompt（`projects/[项目名称]/features/[页面英文ID]/prompts/YYYYMMDD-[功能名称]-Prompt.md`）。
建议下一步：
- 若 Axhub Make 尚未启动，请执行 `启动[项目名称]`
- 若当前还没有原型页面，请执行 `执行原型生成`
- 若当前已有原型页面并准备直接迭代，可直接修改 `axhub-make/src/prototypes/[页面英文ID]/`
- 若后续改了 PRD，请执行 `执行Prompt同步`
```

## 执行条件

- 用户提供了明确的需求描述
- 目标项目目录已存在
- 对于升级页面，已具备最少可理解的输入材料

## 注意事项

- 确保需求/功能名称清晰明确，避免使用模糊或过于宽泛的名称
- 文件名必须严格遵循 `YYYYMMDD-功能名称.md` 和 `YYYYMMDD-功能名称-Prompt.md` 格式
- 生成的 PRD 文档应包含完整的业务背景、功能需求、用户角色、数据字典和业务流程
- 生成的 Prompt 应详细描述页面布局、UI 组件和交互逻辑
- 本流程不强制自动启动 Axhub Make；启动预览由 `07-项目启动与预览流水线` 负责
