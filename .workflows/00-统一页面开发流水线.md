# 统一页面开发流水线

## 触发词

`/开发页面`、`/页面开发`、`开始开发`、`我要做页面`

## AI 执行步骤

1. 识别用户意图（新增/升级/迭代）
2. 决定启动哪条具体流水线
3. 按目标流水线规范执行

以下为流水线决策映射表：

| 场景 | 命令/触发词 |
|------|------------|
| 从需求开始新页面 | `执行需求梳理` → 走 02 |
| 升级旧页面（从材料） | 放入 `workbench/_incoming/` → `执行需求梳理` → 走 02 |
| 继续迭代已归档 | `执行恢复` → 走 09 恢复 → `执行需求梳理` → 走 02 |

---

## 一句话说明

**无论"新增页面"还是"升级旧页面"，都走同一条主线，只在第一步判断材料来源。**

---

## 统一主线（记住这一条就够了）

```
判断来源 → 准备材料 → 生成/更新PRD → 启动预览 → 生成/修改原型 → 归档
```

---

## 第一步：判断材料来源（自动/手动）

AI 会先问你（或自动检测）：

| 场景 | 材料来源 | 操作 |
|------|----------|------|
| **A. 全新页面** | 只有需求描述/草图/想法 | 直接进入第二步 |
| **B. 升级现有页面（传统）** | 有历史资料包（HTML导出/截图/旧代码） | 先放入 `workbench/_incoming/`，再进入第二步 |
| **C. 继续迭代已归档页面** | 页面已在 `projects/xxx/features/xxx/` 中 | 先执行 `恢复原型`，再进入第二步 |
| **D. 精确还原旧页面** | 有完整Chrome扩展导出包（包含 theme.json、screenshot.png、结构数据等） | 使用 `执行页面还原` `还原老页面` `还原旧页面` `升级旧页面` 触发 10 号流水线进行高精度还原 |

**关键原则**：
- 历史资料包（HTML导出等）**临时使用**，盘点完后**无需长期保留**
- 不需要专门的 `history` 文件夹，避免 clutter
- 旧资料的价值是"快速理解现状"，不是"永久存档"

---

## 第二步：准备材料（统一入口）

### A. 全新页面
- 用户提供：需求描述、参考截图、草图等
- 放入：`workbench/_incoming/YYYY-MM-DD/<pageId>/`

### B. 升级旧页面（有历史资料，传统方式）
- 用户放入：`workbench/_incoming/YYYY-MM-DD/<pageId>/`
- AI 执行：**快速盘点**（可选）
  - 读取资料包中的关键信息（截图、content.md、theme.json）
  - 生成简要分析报告到 `workbench/_incoming/.../analysis-report.md`
- 只提取当前页面改造所需的核心信息
- 盘点完成后，资料包可删除或保留（用户决定）

### C. 继续迭代已归档页面
- 执行：`npm run restore:prototype -- <project> <pageId>`
- 结果：原型恢复到工作台，PRD 恢复到工作台

### D. 精确还原旧页面（Chrome扩展导出包）
- 用户放入：`workbench/_incoming/YYYY-MM-DD/<pageId>/`
- 放入完整导出包：包含 `manifest.json`, `screenshot.png`, `theme.json`, `sections/`, `structure/`, `content.md` 等
- 触发：`执行页面还原` 或 `还原老页面`（启动 10 号流水线）
- AI 执行：**高精度还原**
  - 使用 `theme.json` 中的精确设计令牌生成主题
  - 按 `sections/` 分段逐步还原页面
  - 使用 `visual-diff` 验证还原精度
  - 还原目标：≥ 85% 视觉相似度

---

## 第三步：生成/更新 PRD（统一）

无论哪种来源，都执行相同操作：

1. **读取输入**：
   - 全新页面：读取需求描述
   - 升级旧页面：读取需求 + 历史资料分析
   - 迭代页面：读取现有 PRD + 新需求

2. **生成/更新 PRD**：
   - 工作台 PRD：`axhub-make/src/docs/<pageId>-PRD.md`
   - 迭代记录：`projects/<project>/features/<pageId>/iterations/YYYYMMDD-<描述>.md`

3. **生成 Prompt**：
   - `projects/<project>/features/<pageId>/prompts/YYYYMMDD-<描述>-Prompt.md`

**触发词**：`执行需求梳理`

---

## 第四步：启动预览（统一）

```bash
npm run dev:axhub-make
```

**触发词**：`启动项目预览`

---

## 第五步：生成/修改原型（统一）

### 场景判断

| 情况 | 操作 |
|------|------|
| 原型不存在 | 执行 `执行原型生成`（基于 Prompt 自动生成） |
| 原型已存在，小改动 | 直接手工修改代码 |
| 原型已存在，大改版 | 执行 `执行原型生成`（覆盖重建） |
| 基于历史资料还原 | AI 读取资料包，快速还原布局，然后手工微调 |

**触发词**：`执行原型生成`、`生成原型`

---

## 第六步：深度补强与同步（可选）

- 需要复杂交互、接口联动或重型 CRUD 演示：执行 `执行原型增强`
- PRD 变更后：执行 `执行Prompt同步`
- 需要正式提交或交付前收口：执行 `执行代码审查`
- 多端并行开发编排：当前仓库暂不使用
- 一般调整：直接改代码

---

## 第七步：归档（统一）

页面阶段性完成后：

```bash
npm run archive:prototype -- <project> <pageId>
```

**结果**：
- 原型归档到 `projects/<project>/features/<pageId>/prototype/`
- PRD 归档到 `projects/<project>/features/<pageId>/prd/`
- 工作台清理，避免分叉

**触发词**：`归档`、`完成归档`

---

## 目录结构（简化版）

```
projects/<project>/
├── features/
│   └── <pageId>/
│       ├── meta.json              # 页面元数据
│       ├── prd/
│       │   └── PRD.md             # 正本PRD
│       ├── iterations/            # 迭代记录
│       ├── prompts/               # 历史Prompt
│       └── prototype/
│           ├── source/            # 源代码快照
│           └── export/
│               ├── zip/           # HTML导出
│               └── html/          # 解压后HTML
│
└── legacy-assets/                 # 仅当需要长期保留旧系统资料时
    └── <page>/                    # 可选，非必须
        └── ...

workbench/
└── _incoming/                     # 临时输入材料（用完可删）
    └── YYYY-MM-DD/
        └── <pageId>/
            └── ...

axhub-make/src/
├── docs/<pageId>-PRD.md           # 工作台PRD（临时）
└── prototypes/<pageId>/           # 工作台原型（临时）
```
